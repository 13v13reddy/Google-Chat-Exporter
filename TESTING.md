# Testing Google Chat Exporter

## Automated verification

Run `npm test` and `npm run build` before committing export changes.

### Browser end-to-end tests

Run `npm ci`, `npx playwright install chromium`, and `npm run test:e2e`. Set `GCE_HEADED=1` to show the test browser. Each test gets an isolated profile, the unpacked Chrome extension, synthetic pages at the supported Google Chat/Gmail URLs, and its own download directory. The tests neither sign in nor use work-chat content. The JSON report, retained failure traces, browser errors, job metadata, and light/dark UI captures are written under `test-results/` and are excluded from packages and Git.

These tests run the actual popup → background → selected Chat frame → extraction → packaging → native download path. They reopen TXT/Markdown files and HTML ZIPs, compare message IDs, validate attachment bytes and UTF-8, and exercise date filters, old-parent/new-reply context, incremental saves, incomplete threads, failed attachments, blocked downloads and retries, cancellation, collector reload/closure, worker restart, source navigation, popup reopening, Gmail account/frame selection, thread deep links, unavailable files, and auto-export. UI cases cover saved settings, long conversation names, empty dates, unavailable Chat, visible controls, dark-mode propagation, dismissing results without deleting files, and uncaught page errors.

Playwright enables Chromium focus emulation by default. The minimized-window case disables it on the collector and requires either a resumable pause or a file containing the exact expected message IDs, because automated browsers can keep minimized pages rendering. These synthetic pages and DevTools-controlled rendering policies cannot establish how an installed Vivaldi session handles occlusion or display sleep. Live rendering checks remain separate. Firefox's shared code is covered by the Node suite; these browser tests run Chromium, not an installed Firefox add-on. Native operating-system file opening and authenticated attachments also require manual checks.

The Node test suite loads both browser sources with synthetic DOM and browser APIs. It covers history traversal, overlapping viewports, collapsed replies, deletion placeholders, parent/reply relationships, date filters, incremental baselines and context, cancellation, incomplete scans, and conversation changes behind fixed PWA addresses.

Packaging tests load the shipped JSZip library, generate and reopen real archives, and verify HTML, CSS, attachment bytes, UTF-8 text, and thread metadata. TXT and Markdown downloads are also decoded. Firefox's blob-URL download path is exercised with Node's Blob implementation. A synthetic 10,000-message Markdown export checks that message IDs and Unicode text survive packaging.

Result-card tests cover completed/pending/interrupted downloads, unavailable or foreign files, opening errors, stale status responses, persistent notifications, popup relay deduplication, and dismiss/resize message validation. The native Open API is mocked; these tests verify that the call occurs directly in the extension page's click handler, not that an operating-system application opens.

Background-status regression tests cover hidden history waits, hiding and returning before a throttled timer fires, pausing/resuming a thread without losing replies, and cancelling a hidden export without saving a partial file. Worker/API fixtures verify popup reopening, status recovery in a new worker, source-tab reload/closure, packaging after Chat closes, native download completion/interruption/resumption, unchanged checkpoints on interrupted saves, and dismissal across popup instances. Popup fixtures also reject stale status snapshots and prevent an older job's completion from unlocking a newer running export.

Collection-window fixtures verify that full-history toolbar/context-menu requests use a separate, unfocused window, preserve account/proxy/container context, remove thread deep links, and refuse a different conversation. They cover duplicate requests, cancellation during startup, auto-export recursion prevention, restoring minimized windows, original-tab progress/result notifications, packaging after automatic helper closure, and protection against reusing a retained tab ID after browser restart. Placement fixtures verify temporary side-by-side bounds, restoration, and preservation of later user resizing. Narrow-layout thread fixtures require the main timeline to be revealed before further history traversal and restore a previously open thread. Paint-wait tests hold animation callbacks while the document reports visible, verify persistent pause/resume, and verify cancellation clears callbacks and timers. Browsers without the window API keep the original in-tab path.

Theme tests cover system defaults, saved light/dark choices, updates across popup/notification/result contexts, stale preference reads, failed storage writes, and notification listener cleanup. Progress-notification tests run the actual content UI renderer against a synthetic DOM. Thread diagnostic tests retain incomplete-export checkpoint safeguards and verify that TXT, Markdown, and HTML include failure reasons and reply coverage, with safe text escaping.

These tests mock `chrome.*` APIs. They do not prove that an installed extension has the required permissions, selects the right iframe, remains active through browser worker suspension, or successfully fetches authenticated Google attachments.

## Toolbar popup sizing regression (2026-11-04, local time)

The installed Vivaldi toolbar could create an almost invisible 28 × 102 pixel popup even though opening `popup.html` in a normal tab rendered correctly. Accessibility inspection identified the narrow extension web view. The popup body's `max-width: 100vw` constrained its intrinsic width to that initial guest viewport, preventing the host from sizing it to the intended 360 pixels. Removing that viewport-relative cap in both browser stylesheets preserves the fixed popup width.

A new browser regression starts the popup at the observed 28 × 102 viewport and checks that the body retains its 360-pixel intrinsic width and usable form controls. It failed at 28 pixels before the fix and passes afterward. All four popup UI cases pass, including light/dark settings, saved results, input validation, and progress-notification theme changes. This test exercises the sizing feedback condition; Playwright still opens the extension page as a tab rather than pressing Vivaldi's native toolbar button. The installed extension was reloaded after checking that no export was active.

## Network collection verification (2026-11-04, local time)

The background collector replaces rendering-dependent traversal for supported space routes started from the toolbar or context menu. `chat-api.js` contains the positional web-protocol fields and strict response validation. `background-collector.js` manages an inactive, task-owned Chat tab, bounded read requests, retries, filtering, attachment downloads, and packaging. Credentials are read inside Chat's MAIN world and are never returned or stored. No additional browser permissions or dependencies were added.

All 267 Node tests pass. Browser verification covers 24 existing DOM/UI cases and 14 network cases. The DOM fixture now uses explicit `/dm/` routes so its history expansion, rendering waits, companion-window lifecycle, and UI coverage remain exercised. Separate network fixtures run the actual popup, worker, MAIN-world fetch, parser, packaging, checkpoint, native-download, and result-card path. They check exact IDs, deleted placeholders, paginated replies, UTF-8, TXT/Markdown/HTML, offline attachment bytes, original-tab closure, cancellation during a delayed response, 429 retry, sign-in/policy pages, changed schemas, stalled pagination, missing replies, date-filtered parent context, incremental baseline/empty/new results, failed attachments, helper reload/closure, worker restart, and helper loss during media. Network interruption tests caught a race where an injection rejection beat the tab event; either event ordering now retains an interruption and prevents partial packaging.

In installed Vivaldi, a full-history Markdown export completed while the collection tab remained hidden and unfocused. A settled measurement observed zero animation frames while message counts continued increasing. It captured **36,250 unique message IDs across 23,200 topics**, including **13,050 replies in 2,053 threads**. A separate raw-response scan, using a different page size, reached Chat's explicit end-of-history flag and reconciled every advertised reply count. Comparing that raw ID/parent map with the downloaded Markdown found **zero missing IDs, unexpected IDs, duplicates, or incorrect parent links**. This verifies all history that this signed-in session returned for the tested space; it does not establish access to retention-deleted or otherwise inaccessible history.

The first complete run exposed four image-only posts and a Drive attachment that were preserved losslessly as unfamiliar structured content, with a warning and no checkpoint. Added image/GIF and Drive-link parsing resolved those cases. A second installed full export again matched every ID and parent, contained no structured fallback or warning, completed its native download, and saved the API checkpoint at the newest captured message timestamp. The helper closed automatically. A separate hidden-page authenticated PNG read returned 40,678 bytes with an image MIME type. That check found that image attachment tokens require `FIFE_URL`; using `DOWNLOAD_URL` failed. The parser and regression coverage now retain the correct image URL type. Proxy HTML responses cannot be mistaken for successfully downloaded media in the network collector.

The earlier warning-bearing test download and task-owned tabs/resources were removed. The final native archive remains in Downloads. No Chat messages were sent, edited, or deleted. Only progress metadata and checkpoint hashes persist in extension storage; network response captures, work content, credentials, and diagnostic resources are absent from Git and packages. The original blue-header UI, text controls, and dark mode remain unchanged.

Remaining scope: explicit `/dm/` routes and auto-export still use the DOM path and its rendering restrictions. The private Chat web protocol can change; unsupported responses fail explicitly. Native Firefox, other signed-in accounts/Gmail/PWA variants, large authenticated media archives, Drive-document downloads, and operating-system file opening remain separate manual release checks. Unfamiliar empty-body payloads are preserved as structured data with a warning and no checkpoint; inaccessible media retain their original links and also withhold the checkpoint. A worker/browser restart interrupts active network collection rather than resuming it, but native download outcomes are reconciled. No debugger permission remains.

## Known boundaries

- The DOM fallback uses repeated idle checks to infer that it has reached the start. There is no authoritative total-message count for that fallback. Very slow history responses still require live verification; reply-count checks verify discovered threads, not that every parent in the space was discovered.
- Explicit `/dm/` full-history toolbar/context-menu exports use a separate collection window. Supported space routes now use the network collector described above. Leave it visible and unminimized so Chat can render history. Hidden, covered, or locked-screen windows pause until painting resumes. Placement uses side-by-side windows on desktop screens at least 1000 pixels wide; smaller displays require the user to keep the collection window visible. Loaded-only and automatic exports still use the original tab and pause DOM work while hidden. Media fetching and background packaging do not require the popup to stay open. An unfinished extraction or packaging job cannot resume after a browser restart; its retained status becomes interrupted.
- Packaging uses temporary extension API activity to avoid Chrome's idle worker shutdown. Browser shutdown, crashes, and enforced lifetime or memory limits can still interrupt it; progress metadata survives, while an unfinished archive does not. See [Chrome's worker lifecycle](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle).
- Incremental mode selects newly timestamped messages and previously unseen untimestamped entries. It does not detect an edit to an older message when that message retains its original timestamp. Use a full re-export when updates to old messages must be reflected.
- The exporter writes separate archive files. It does not synchronize changes back into earlier downloads.

## Manual release checks still required

| Area | Check |
| --- | --- |
| Installed desktop extension | Reload the extension and Chat. Export TXT, Markdown, and HTML from both the popup and right-click menu. Reopen the downloaded files. |
| Result card | Apply the added `downloads.open` permission. Confirm Open waits for completion, opens the exact downloaded file, and × dismisses the card without deleting the file. Check native Open in Chromium and Firefox, including the embedded extension frame. |
| Appearance | Toggle Dark mode while a progress or result notification is visible; verify immediate updates and persistence after reopening. Check native controls, focus rings, disabled actions, and errors in Chromium and Firefox. |
| Browser coverage | Run installed-extension checks in Chromium and Firefox desktop. Test Firefox Android separately because its thread layout can differ. |
| Chat layouts | Check standalone Chat, Gmail's embedded Chat frame, installed PWA windows, and the supported MCAS proxy hosts. |
| Authenticated attachments | Verify images, files, audio, and video from actual Google-hosted URLs. Confirm failed attachments warn and prevent checkpoint advancement. |
| Incremental updates | Export a baseline, then use an existing older thread that receives a new reply. Confirm the next export contains the reply and labeled parent context. |
| Cancellation and navigation | Cancel during history and media loading. Change conversations during export, including a PWA whose outer URL stays fixed. Confirm no mixed-conversation file is saved. |
| Downloads and worker lifecycle | Interrupt a download, restart the browser worker, and confirm its checkpoint remains unchanged. A completed download must advance it. |
| Background status | Start a full-history space export, close the popup, switch tabs/conversations, and reopen the extension. Confirm its inactive network helper keeps collecting, Cancel closes it with a retained outcome, and packaging closes it automatically. Reload/close that helper during history or media and require a persistent interruption with no partial save. Verify the download result in the popup after source closure. Separately test the explicit `/dm/` companion fallback, hidden loaded-only/auto-export waits, worker restart, and pending/completed download recovery. |
| Scale and timing | Check a long real conversation, slow history loading, background tabs, and large media archives while watching responsiveness and memory. The synthetic Markdown check does not establish a safe limit for media archives. |
| Language and number formats | Check the Chat UI language in use. Unrecognized reply-count labels must leave the export unverified and its checkpoint unchanged. |

Use a test space for cases requiring new messages, edits, or deletions. Do not modify a work conversation merely to manufacture a test case.
